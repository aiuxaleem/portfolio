context:
  problem: "At Colaberry, branded work is needed by people who are not designers: developers building product and web screens, and colleagues in sales and marketing who need decks, pages and campaign assets. The system's goal is written into its principles: one system, many makers, so that a marketer, a developer and an AI agent produce the same brand from the same source."
  constraints:
    - "It had to work as plain files a team can open or copy. There is no build step."
    - "The brand's cherry red does not pass contrast for body text on white, so the palette needed a rule for where each red may be used."
    - "People with no design or code background had to be able to get a usable result by describing what they need."
process:
  summary: "The system was built in layers: tokens first, then components, then templates, then the documentation and hand-off paths that let other people use it without me."
  steps:
    - title: "Tokens before components"
      body: "Colour ramps, type, spacing, radius, shadow and motion are CSS custom properties with a JSON mirror for other tools: 187 base values and 44 dark-theme overrides. In dark theme the foreground inverts with the background and the cherry red stays constant."
    - title: "Twenty components, each with a contract"
      body: "Every component ships with typed props and a short usage note written for an AI agent, so a person and a model read the same rules. The documentation renders the same code that ships."
    - title: "Templates for the work people actually request"
      body: "Fifteen templates: deck slides, a web page, a social media kit for seven platforms, a WhatsApp batch kit, an email newsletter, an event poster, an Eventbrite kit, a standee, a brochure, a one-pager, a comparison sheet, a certificate, a case study, a proposal and a business card."
    - title: "A path for each kind of maker"
      body: "Marketing and non-technical colleagues start a request with the words \"Using the Colaberry design system\" and ask for three options. Developers link one stylesheet and use the bundled components. Each template has a Download button for a full-size image and an Edit button that copies the right prompt."
    - title: "Five brands on one foundation"
      body: "The same idea carried across five brands. The components stay the same; each brand is a set of tokens held as data: 11 colour roles in light and dark, typefaces, radius, shadow and motion. All five use the same 44 token names and the same component classes, so a new brand is a token file, not a rebuild. Each brand generates a stylesheet for developers, a brand guide for designers and a prompt block for AI tools."

ai:
  summary: "The system is written to be read by an AI agent as well as by people, so asking Claude for a branded asset gives an on-system result."
  behaviour:
    - "A skill file tells the agent what to read first: the brand guide, the implementation guide, the tokens, the components and the logo files."
    - "Every component has a usage note and typed props, so the agent uses the real component in place of inventing markup."
    - "If the skill is invoked with no brief, the agent asks what to build."
  guardrails:
    - "A lint configuration warns on raw hex colours, raw pixel values, fonts outside the system, undeclared props and imports of component internals."
    - "The prompt recipe asks for three options, so a person chooses and refines in plain words."
  humanInLoop: "Strategy, brand direction and every design decision were mine. Claude ran as the executing agent for each build step."
decisions:
  - decision: "Text-bearing red moved one step darker."
    tradeoff: "White on the brand cherry measured 3.8:1, below the 4.5:1 that body text needs. The next step down reaches 4.7:1. The brighter cherry stays for large type and accents."
  - decision: "Motion is a token, like colour."
    tradeoff: "Each brand moves in character: Enterprise stays composed, Training springs a little, Career Pathways Network never startles. It costs one more thing to define per brand, and it keeps motion out of hand-written component code."
  - decision: "No build step."
    tradeoff: "Static HTML, CSS variables and plain React files mean anyone can open or copy the system. The cost is that it is not yet an installable package."
  - decision: "Show the contrast failures in the docs."
    tradeoff: "The audit table lists cherry text on white as a body-text fail, next to the pairings that pass, so nobody has to rediscover it."
