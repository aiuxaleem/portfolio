context:
  problem: Loan onboarding is where a lender wins or loses a customer, and it is also where the rules are strictest. Every screen has to be clear to the applicant and correct for compliance. Designing these screens one by one makes both harder to keep consistent.
  business: Latitude Financial Services is an Australian consumer finance company offering personal loans and credit cards. I joined NTT DATA’s web team for the account as a product designer, working with a small agile team of developers, designers and business analysts. The company already had a design system and design language. My job was to design inside it and help it grow where onboarding needed more.
  constraints:
    - Every screen had to follow the client’s design system and design language.
    - Compliance guidelines set what onboarding screens had to show and how.
    - Web pages also had to meet digital marketing and search requirements.
    - Work ran in quarterly sprints with daily stand-ups and tasks tracked in Jira.
research:
  summary: In a regulated product, the design system is not only a visual library. It is how compliant patterns get reused. When a pattern lives in the system, it is checked once and used everywhere. When it lives in one designer’s file, it has to be checked again every time.
  insights:
    - Onboarding needed patterns the general system did not fully cover yet.
    - Fixing the system was more durable than fixing a single screen.
    - Web, mobile and card pages needed to feel like one product, not three.
process:
  summary: I started from the system and the rules, improved the system where onboarding needed it, then designed the flow and carried the same foundations to mobile and cards.
  steps:
    - title: Learn the system and the rules
      body: I worked through the client’s design system, design language and compliance guidelines before designing screens, so the constraints shaped the work from the start.
    - title: Improve the system with the Design Manager
      body: I worked with the Design Manager to improve and maintain the design system, with a focus on the patterns loan onboarding pages depend on.
    - title: Design onboarding from the system
      body: I designed the new loan onboarding screens in high fidelity, using only system components and following the compliance guidelines.
    - title: Carry it to mobile and cards
      body: I redesigned mobile app screens and the Gem Visa credit card designs on the same system, so each surface looked and behaved like part of one product.
    - title: Align with marketing
      body: I worked with the digital marketing team to optimise page layouts and keep web pages in line with search requirements.
decisions:
  - decision: Build onboarding only from design system components, with no one-off parts.
    tradeoff: Some layout ideas had to wait for the system to support them, in exchange for screens that stayed consistent and compliant.
  - decision: When onboarding needed a pattern the system lacked, improve the system with the Design Manager rather than detach a local copy.
    tradeoff: Slower than patching one screen, but every later screen got the fix for free.
  - decision: Use the same foundations across onboarding, mobile and the credit card pages.
    tradeoff: Less room for page-specific styling, in return for one experience customers recognise across surfaces.
outcomes:
  summary: New loan onboarding screens were designed strictly on the design system and its compliance guidelines. The system itself was improved and maintained for onboarding, and the same foundations carried through to mobile app screens and the Gem Visa credit card designs.
quote: In lending, the design system is how compliance scales.
reflection:
  summary: This work showed me that in regulated products, the system does more than keep things consistent. It is where the rules live.
  learnings:
    - Fix the system, not the screen. The fix then reaches every page that uses it.
    - Compliance is easier to keep when it is built into components rather than checked at the end.
    - I would capture onboarding completion data before redesigning, so the outcome could be measured.
    - Today I would write the compliance rules into the system documentation, where people and AI tools can both read them.
